# Bootstrap environment

How to recreate, from nothing, the locked-down container used to build this repo
with Claude Code.

- **The image** (`bootstrap.def`) holds only OS tools: git, gh, vim, yamllint,
  ShellCheck and so on.
- **The sandbox home** (`~/projects/llm-bootstrap/home`) holds Claude Code, its login
  and the git/gh config. It persists between runs, and your real home is never
  mounted.
- **`run-bootstrap.sh`** starts the container with `--containall --cleanenv`, binds
  only `~/projects/llm-bootstrap/work` at `/work`, and passes secrets with
  `--env-file`.

Set `LLM_BOOTSTRAP_DIR` to use a directory other than `~/projects/llm-bootstrap`.

## 1. Build the image

Building needs `--fakeroot`, which requires subuid/subgid entries for your user.

```sh
mkdir -p ~/projects/llm-bootstrap
cp bootstrap.def run-bootstrap.sh ~/projects/llm-bootstrap/
cd ~/projects/llm-bootstrap
singularity build --fakeroot bootstrap.sif bootstrap.def
```

## 2. Create `secrets.env`

Create a **fine-grained** personal access token at
<https://github.com/settings/personal-access-tokens>:

- Repository access: only `jmtovar/local_llm_images`.
- Permissions:

  | Permission | Access | Used for |
  |---|---|---|
  | Contents | read and write | push branches and tags |
  | Pull requests | read and write | `gh pr create` |
  | Workflows | read and write | push changes under `.github/workflows/` |
  | Actions | read | `gh run watch` |
  | Issues | read | `gh issue view` |
  | Metadata | read | required |

Then:

```sh
vim ~/projects/llm-bootstrap/secrets.env    # one line: GH_TOKEN=github_pat_...
chmod 600 ~/projects/llm-bootstrap/secrets.env
```

`run-bootstrap.sh` refuses to start unless the file is `600`. It passes the file with
`--env-file`, so the token never appears on a command line, where `ps` would show it.

## 3. Start the container

```sh
~/projects/llm-bootstrap/run-bootstrap.sh
```

This gives you a login shell in `/work`, which is `~/projects/llm-bootstrap/work` on
the host.

## 4. Install Claude Code (inside the container)

```sh
curl -fsSL https://claude.ai/install.sh | bash   # installs to ~/.local/bin in the sandbox home
claude --version
```

Source: <https://docs.claude.com/en/docs/claude-code/setup>. Claude Code updates
itself in the sandbox home; rebuilding the image doesn't affect it.

## 5. Set up git (inside the container)

```sh
gh auth status          # uses GH_TOKEN from secrets.env
gh auth setup-git       # lets git push over HTTPS with that token
cd /work
git clone https://github.com/jmtovar/local_llm_images.git
cd local_llm_images
git config --local user.name "<your name>"
git config --local user.email "<id>+<user>@users.noreply.github.com"
```

- The identity is set with `--local` (this clone only), never `--global`.
- `gh auth setup-git` itself writes a credential helper to the global `~/.gitconfig`.
  Here that is the sandbox home, not your real one.

## 6. Work

```sh
cd /work/local_llm_images
claude
```

`CLAUDE.md` in the repo holds the rules every session follows.
