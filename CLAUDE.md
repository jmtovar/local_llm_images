# CLAUDE.md

Rules for working in this repo. They copy the owner's standing preferences; follow
them in every session.

## Project

- Ollama images for a CPU-only x86-64 laptop with ~16-24 GB RAM, run with
  Singularity. Conversations must never leave the machine.
- Current plan: `docs/plans/initial-scaffolding.md`. Don't start later milestones (dev
  image, web UI, web search, bubblewrap wrapper) until asked.

## Hard constraints

- **Public repo, no machine details:** never commit details of the owner's machines
  (CPU model, RAM size, disk or partition layout, encryption set-up, usernames,
  hostnames, distro, real home paths). Use generic wording, e.g. "a CPU-only x86-64
  laptop with ~16-24 GB RAM" and "an encrypted location of your choice"; example
  paths use placeholders like `~/llm-data`. The brief (`KICKOFF.md`) stays outside the
  repo.
- **No Qwen models**, and no models fine-tuned from or derived from Qwen, not even as
  examples. Check the base model of anything from Hugging Face.
- **Pin everything:** base images by digest, GitHub Actions by commit SHA (with a
  version comment), models by explicit quantisation tag and manifest digest. Record
  the source URL of every pinned version and digest.
- **Unprivileged Singularity:** images must run as a normal user, with nothing written
  to `/root` and nothing installed into a home directory.
- **SingularityCE and Apptainer:** scripts and docs use the `singularity` command,
  `${SINGULARITY:-singularity}`, `SINGULARITY_CACHEDIR` and `SINGULARITY_TMPDIR`, and
  only flags both runtimes support. Apptainer's warning about legacy `SINGULARITY_*`
  names is harmless.
- **Privacy defaults:** `OLLAMA_HOST=127.0.0.1:…` (localhost only),
  `OLLAMA_NO_CLOUD=1`, `OLLAMA_DEBUG=0`, no `:cloud` model tags.
- **Labels:** every image carries `io.github.jmtovar.local-llm-images.accelerator`
  (`cpu`), `io.github.jmtovar.local-llm-images.arch` (`amd64`) and a one-line
  `org.opencontainers.image.description`. Builds pin `linux/amd64`. A different
  accelerator or architecture means a new image name (e.g. `ollama-<model>-cuda`),
  never a different tag.
- **Verify, don't assume:** check versions, paths and tags against their source, and
  mark anything unchecked as unverified. Lint (yamllint, shellcheck, actionlint)
  before committing.

## Versioning

- Semantic Versioning, **digits only, never a `v` prefix**, anywhere: git tags, image
  tags, labels, CHANGELOG and docs. Releases are `X.Y.Z`; prereleases are
  `X.Y.Z-alpha.N` and `X.Y.Z-beta.N`.
- Upstream versions with a `v` prefix (e.g. Ollama `v0.40.2`) are stored as plain
  digits (`0.40.2`) in our labels.
- Bump policy (impact decides; the commit type follows it):
  - **MAJOR:** breaking change to how images are run (env defaults removed or
    renamed, paths changed, script arguments changed). Commit `<type>!:` or a
    `BREAKING CHANGE:` footer.
  - **MINOR:** new model image, Ollama minor upgrade, changed model weights, new
    features. Commit `feat`.
  - **PATCH:** fixes, Ollama patch upgrade, docs, workflow changes that don't affect
    behaviour. Commit `fix`; `docs`, `ci`, `chore`, `style`, `refactor` and `test` are
    PATCH or no release.
- Tags are annotated, with the version alone as the message:
  `git tag -a X.Y.Z -m "X.Y.Z"`.
- Release `X.Y.Z` only from a commit on `main`, after a `chore/release-X.Y.Z` PR has
  moved the Unreleased entries under `## [X.Y.Z] - YYYY-MM-DD` in CHANGELOG.md.
  Prereleases may be tagged on any branch and are noted under Unreleased.
- Tag pushes always need the owner's confirmation first.

## Git workflow

- Never commit to `main`. Work on `<type>/<short-description>` branches (types: `feat`,
  `fix`, `docs`, `style`, `refactor`, `test`, `chore`, `ci`); releases use
  `chore/release-X.Y.Z`.
- Conventional Commits: `<type>(<scope>): <summary>`.
- Each commit is a self-contained, testable change. Push after each commit so CI tests
  it. Squash the branch only when the owner asks.
- Open PRs with `gh pr create --base main` and a clear, brief description that
  includes `Closes #N`. Then stop and report that the PR is ready.
- **Never run `gh pr merge`.** The owner merges every PR in the browser.
- `git config --local` only, never `--global`.

## Writing and code style

- British English in all prose (README, CHANGELOG, comments, commit and PR text).
  Never change upstream identifiers or spec keys (e.g.
  `org.opencontainers.image.licenses`).
- Be brief in chat, commit messages, PR bodies, CHANGELOG entries and comments.
- Dates in ISO 8601: `YYYY-MM-DD`, `YYYY-MM-DDTHH:MM`.
- Use vim in any shell instructions (e.g. `vim secrets.env`).
- Brief inline comments for non-obvious logic; readable code over clever one-liners.
- File header on every new file, in its comment syntax (after the shebang in scripts,
  after any `# syntax=` line in Dockerfiles, an HTML comment in Markdown; skip formats
  without comments):

  ```
  Generated by: <model name and version>
  Generation date: <YYYY-MM-DD>
  ```

  Add `Last modified by:` and `Last modified:` only on significant later changes.

## Working with the owner

- Disagree openly when there is a better approach; flag trade-offs and misconceptions;
  no hedging or flattery. Once the owner decides, carry it out well.
- Cite sources; distinguish fact from inference; say when unsure; ask rather than
  assume.
